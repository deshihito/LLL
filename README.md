# LLL

動的カードゲーム **LLL** のWebサービスとDiscord補助サービスを同一リポジトリで管理するための雛形です。

現時点では、アプリケーション実装・Supabase接続・カードゲームのルール実装は含めていません。将来の責務分離と開発単位が分かるように、ディレクトリ構成と設計メモだけを用意しています。

## 構成

```text
LLL/
├── apps/
│   ├── web/                  # プレイヤー向けWebアプリ
│   └── discord/              # Discord補助サービス（Bot / コマンド / イベント）
├── packages/
│   ├── domain/               # カード、デッキ、ゲーム状態などの共有ドメインモデル
│   ├── config/               # 環境変数・アプリ共通設定の型と検証
│   └── shared/               # WebとDiscordで共有する汎用型・定数・ユーティリティ
├── docs/
│   ├── architecture.md       # 全体設計と将来の分割方針
│   └── decisions/             # 設計判断の記録（ADR）
├── infra/
│   ├── supabase/              # 将来のSupabase設定・マイグレーション置き場（未作成）
│   └── deployment/            # デプロイ設定置き場
├── tests/
│   ├── integration/           # サービス間・DB接続を含むテスト
│   └── fixtures/              # テスト用カード・ゲーム状態
└── .github/workflows/         # CI/CD設定置き場
```

## 方針

- WebとDiscordは独立してデプロイできる構成にする。
- ゲームルールやカードデータの基準は`packages/domain`に集約する。
- Supabaseは将来`infra/supabase`と各アプリのデータアクセス層から接続する。今回はDBやマイグレーションを作成しない。
- Discord固有のイベント処理とWeb固有のUI/APIを共有パッケージへ持ち込まない。
- 認証、対戦、カード編集、管理機能などは実装開始時に機能単位で追加する。

## 開発開始時の想定

実装フェーズでは、採用するフレームワークに合わせて各アプリの`package.json`、ビルド設定、環境変数サンプル、テスト設定を追加してください。現段階では技術選定を固定していません。
