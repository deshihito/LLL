## 1. 次タスク：Supabase適用確認とユーザー接続

### 目的

ログインユーザーをSupabase上のユーザー情報・設定情報へ接続する。

### 実装内容

1. SQL Editorで以下を順番に適用する。
   - `20261002000000_initial.sql`
   - 未適用の場合のみ`20261002010000_user_and_generation_foundation.sql`
2. `profiles`自動作成を確認する。
3. `user_settings`自動作成を確認する。
4. ログイン中ユーザーのプロフィールを取得する。
5. 表示名を更新できるフォームを追加する。
6. RLSで他ユーザーの情報が取得できないことを確認する。

### 完了条件

- Google／Discordログイン後に`profiles`が存在する。
- ユーザー名とメールアドレスが画面に表示される。
- 表示名の更新が再ログイン後も保持される。
- 未ログインユーザーはデータを取得できない。

## 2. カード画像アップロードとカード下書き

### 目的

カード生成前の画像をユーザー単位で安全に保存する。

### 実装内容

1. カード生成画面にファイル選択を実装する。
2. 画像形式を`png`、`jpg`、`jpeg`、`webp`に限定する。
3. ファイルサイズ上限を10MBにする。
4. Storageの`card-images/{user_id}/`へアップロードする。
5. `cards`へ`generation_status = 'draft'`で登録する。
6. `card_generation_jobs`へ`queued`で登録する。
7. アップロード中・失敗・完了状態を表示する。

### 完了条件

- ログインユーザーの画像だけが取得できる。
- 他ユーザーのStorageパスへアクセスできない。
- 画像とカード下書きが紐づいている。
- 失敗時に再試行できる。

## 3. Geminiカード生成API

### 目的

画像からカード情報を生成し、既存のカード下書きを更新する。

### API

`POST /api/generate-card`

### 入力

```ts
{
  jobId: string;
  cardId: string;
  imagePath: string;
}
```

### 処理

1. Auth.jsセッションを確認する。
2. `jobId`と`cardId`がログインユーザー所有かRLSで確認する。
3. ジョブを`processing`へ更新する。
4. Storage画像をサーバー側で取得する。
5. Gemini APIへ画像と固定JSONスキーマを送信する。
6. 生成結果をバリデーションする。
7. `cards`へタイトル、説明、ステータス、技、program_flowを保存する。
8. `card_skills`へ最大3件保存する。
9. ジョブを`succeeded`へ更新する。
10. エラー時は`failed`とし、`error_message`を保存する。

### API出力

```ts
{
  jobId: string;
  cardId: string;
  status: "succeeded" | "failed";
}
```

### 制約

- Geminiキーはサーバーコードでのみ使用する。
- `SUPABASE_SERVICE_ROLE_KEY`をブラウザへ渡さない。
- AI出力をそのままDBへ保存せず、数値・配列・文字数を検証する。
- 1カードにつき技は最大3件。
- 技の威力は0〜200。
- APコストは初期値50。

### 完了条件

- 画像1枚からカード1件を生成できる。
- 生成中状態が画面に反映される。
- 生成失敗時に再試行できる。
- 不正なAIレスポンスをDBへ保存しない。

## 4. バインダーDB接続

### 実装内容

- ログインユーザーの`cards`だけ取得する。
- カード種別で絞り込む。
- 作成日・タイトルで並び替える。
- カード詳細を表示する。
- 自分のカードだけ削除できる。
- カードが0件の場合は空状態を表示する。

### 完了条件

- 仮データを使用しない。
- DBのカード件数と画面表示件数が一致する。
- 他ユーザーのカードが表示されない。

---

## 5. デッキDB接続

### 実装内容

- デッキ作成・名称変更・削除。
- `deck_cards`への追加・削除。
- `slot_index`を1〜20で管理する。
- 1デッキ20枚を超えて登録できない。
- 同じカードを同じデッキへ重複登録しない。
- 保存前の変更と保存済み状態を分ける。

### 完了条件

- DBを再読み込みしてもデッキ構成が保持される。
- 20枚制限がUIとDBの両方で機能する。
- 所有していないカードを登録できない。
