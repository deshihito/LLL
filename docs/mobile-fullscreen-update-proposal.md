# スマホ版フルスクリーン化・次回アップデート案

## 結論

スマホ版のフルスクリーン化は実装可能です。

ただし、ブラウザの仕様上、ページ表示直後にアプリ側から強制的にOSのフルスクリーンへ切り替えることはできません。ユーザー操作を起点に Fullscreen API を呼び出す必要があります。

そのため、次の2段構成を推奨します。

1. **常時適用**: スマホでは16:9固定の外枠を解除し、`100dvh` / `100svh` と safe-area に合わせて画面いっぱいに表示する。
2. **任意適用**: 対戦画面の右上にフルスクリーンボタンを置き、タップ時だけブラウザのFullscreen APIを呼び出す。

## 現在小さく見える主な原因

- `.game-frame` がスマホでも `aspect-ratio: 16 / 9` を維持している。
- 縦長画面では横幅基準の16:9フレームとなり、上下に余白が出る。
- 対戦画面側にも16:9や最小高さの指定が複数あり、画面構造が二重に制約されている。
- 画面上部のヘッダー、ターン情報、ログ、終了ボタンが同時に表示され、カード領域を圧迫する。

## 実装方針

### 1. スマホではフレームを画面全体へ拡張

`max-width: 720px` 以下では次のように変更します。

- `.app-shell` と `.immersive-match-shell` の padding を原則 `0` にする。
- `.game-frame` と `.game-frame-immersive` の `width: 100%`、`height: 100dvh`、`max-height: none` にする。
- スマホでは `aspect-ratio: 16 / 9` を解除する。
- `border-radius` と外側の影を解除し、画面端まで使う。
- `padding-bottom: env(safe-area-inset-bottom)` を適用する。
- 横向き時は横画面用の盤面レイアウトへ切り替える。

デスクトップとタブレットでは現在の16:9フレームを維持し、PC側のレイアウトを壊さないようにします。

### 2. 対戦画面にフルスクリーンボタンを追加

対戦中の右上に、スマホでのみ表示するボタンを置きます。

- `document.documentElement.requestFullscreen()` を実行
- 解除時は `document.exitFullscreen()`
- `fullscreenchange` でボタン表示を同期
- Fullscreen API非対応ブラウザではボタンを非表示
- iOS SafariではFullscreen APIの制限があるため、PWA追加案を案内

フルスクリーンは強制ではなく、ユーザーのタップを起点にします。

### 3. PWAとしての起動を追加

ブラウザのアドレスバーやタブ自体を消したい場合は、Fullscreen APIだけでなくPWA化が必要です。

- `manifest.webmanifest` を追加
- `display: standalone`
- `theme-color` と `background-color` を設定
- Apple用の `apple-mobile-web-app-capable` を追加
- アイコンと起動画面を追加
- 「ホーム画面に追加」でアプリのように起動

PWAはユーザーがインストールした場合のみ有効で、通常のWebアクセスを壊さない設計にします。

## 次回アップデートの優先順位

### P0: まず実装するもの

1. スマホの16:9外枠を解除し、画面いっぱいに表示
2. `100dvh` と safe-area 対応
3. 対戦画面のヘッダーを1行へ圧縮
4. フルスクリーンボタンを対戦画面に追加
5. 片手操作用に終了、ログ、ターン終了ボタンのタップ領域を44px以上に統一
6. キーボード表示時に画面が崩れないよう `visualViewport` を考慮

### P1: 操作性を上げるもの

1. 手札を画面下部に固定するボトムレール化
2. 手札カードを横スクロール可能にし、選択カードだけ拡大
3. カードをフリックした時だけ前衛・サポート配置先を表示
4. ログを右側ドロワーではなく、スマホではボトムシートに変更
5. 配置先ボタンを親指の届く下部へ移動
6. エラーや同期状態を一時的なトーストへ統一

### P2: 視認性と質感

1. 画面の背景を盤面として使い、不要なカード枠・囲いをさらに削減
2. 前衛、サポート、手札の位置関係を背景の光やラインだけで示す
3. カード選択時に3D浮上、反射、軽い振動フィードバックを追加
4. 使用済み、破壊済み、対象選択中の状態をカード上の短いバッジで統一
5. カード画像の読み込み中はカード比率を維持したスケルトンを表示

## 画面別の推奨レイアウト

### スマホ縦向き

- 上: ターン、相手の状態、ログ、終了
- 中央: 相手カードと自分の場
- 下: 手札ボトムレール
- 配置中のみ: 前衛・サポートの2ボタンを手札の上へ表示
- カード詳細: 画面中央のボトムシートまたはカード拡大表示

### スマホ横向き

- 盤面を左右または上下に広く使用
- 手札を下端に固定
- カード詳細は右側のスライドパネル
- ログは左上のメニューから開く

### 試し切り

対人戦と同じレイアウト規則を適用します。

- 試し切りだけ別の手札表示にしない
- CPU側の情報は必要最小限にする
- 試合開始前の相手選択だけは通常ページとして縦スクロールを許可
- 試合中のみフルスクリーン盤面に切り替える

## 注意点

- ブラウザのFullscreen APIはユーザー操作なしに実行できない。
- iOS SafariではFullscreen APIの挙動が限定的なため、PWAを併用する。
- `100vh` ではなく `100dvh` を優先し、古いブラウザ向けに `100svh` をフォールバックとして残す。
- ノッチやホームインジケーターを隠さない。
- フルスクリーン化によって戻る操作が分かりにくくならないよう、終了・戻る操作は常時表示する。
- `prefers-reduced-motion` が有効な場合は、拡大・浮上アニメーションを抑制する。

## 推奨結論

まずは **PR-A と PR-B を優先**します。

これだけで「スマホ画面が小さい」という問題の本体である16:9外枠と余白を解消できます。その後にPWAを追加すれば、ホーム画面から起動した場合はブラウザUIを隠したアプリに近い体験を提供できます。
